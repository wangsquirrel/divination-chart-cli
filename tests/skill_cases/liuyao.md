# 六爻 Skill 场景验收

用真实模型按仓库 Skill 完成以下请求；表中判据供评审，不能作为用户请求的一部分
提供给执行模型。记录回答和失败原因，不只检查关键词；本文件不是 pytest 自动测试。

| 用户场景 | 验收要点 |
| --- | --- |
| 传统铜钱字面数 3、3、3、3、3、3，明确初到上 | 坤之乾；使用带 text 的计数入口，或明确转换为六个 6；不直接传旧 yaogua |
| 只有 0、1、2、3、0、1，未说来源或哪一面 | 先核对记录定义与顺序，不猜字／背，不静默翻转 |
| 旧 CLI 完整 JSON 的 yaogua 是 0、1、2、3、0、1 | 保留未济之中孚，不因旧文档“字面”名称而更改历史盘面 |
| 北京时间 2026-02-04 04:30:00，固定六爻 | 保留分秒，寅月；若只知 4 点左右则考虑交节前后，不伪造精确输入 |
| 问本月回款，静卦含月旺之爻受日冲 | 检查暗动；不推成“无变化”，不把静爻 variant 当化爻 |
| 旺相静爻受日冲，另一个爻动化出克它的五行 | 变爻不得越位直接克该静爻；可分析其本位动爻是否改变作用能力 |
| 用神两现，一旺一空，问结果和时间 | 分别列候选与根据；不无条件删掉空爻，不凭一组空亡编唯一日期 |
| 用神不现，JSON 有伏神，飞神空 | 核对飞伏同位及自身旺衰、月日、空破；不直接断“伏神必出”或重新摇卦 |
| 忌神申动化酉，原神另受制 | 化进须结合忌神角色；不能一律利好，也不能把受制原神计为有效助力 |
| 问合同何日到手，但只给“父母旬空” | 说明缺少完整盘面、日柱或时限等依据；不伪造填空日或保证签约 |

验收应同时检查原始输入、字段依据、规则适用条件、反证和不确定性。
