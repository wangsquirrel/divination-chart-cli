# 六爻应期：条件与候选窗口

在用户问“何时”、日期或时间窗口时读取。依据《增删卜易》“各门类应期总注”、
“旬空”“月破”“两现”等章节，见[来源索引](liuyao-source-map.md)。
这是传统规则下的候选条件，不是统计预测。

## T1 先固定问题与时限

记录所问事件、完成标准、原起卦时间和用户关心的范围。先用核心规则判断支持与阻碍，
再找哪个条件需要解除或兑现。不能仅凭有某个地支就宣布该日事情会发生；不把结果已知
的日期倒填成“预测”。近事以日／时、远事以月／年只是取尺度线索，最终受问题时限约束。

## T2 从关键爻的状态生成候选

| 已有状态 | 可考察的触发条件 | 不能省略的复核 |
| --- | --- | --- |
| 静而有用 | 逢值、逢冲 | 冲是启动还是损伤，仍受旺衰限制 |
| 明动而有用 | 逢值、逢合 | 合也可能牵制；不能凡合必成 |
| 旬空且有气待用 | 出旬、值支填实、逢冲 | 三者不是同一天的同义词；受克无助不能只等出空便许成功 |
| 月破而有作用基础 | 出月、填实、逢合 | 出月以交节算，不是公历或农历月初；还要复核新的月日 |
| 合绊或入墓已经成立 | 冲开相关合、墓 | 先证明是绊、墓，不能只看到六合或墓库字就套规则 |
| 用神有扶但受克 | 克制它的力量被制、用神得扶 | 保留主局是否支持成事的前提 |
| 用神多现或多条动变链 | 分别列候选与触发理由 | 《两现章》有空破爻指示应期的例子，不直接抛弃弱候选 |

## T3 对应到公历并给出反证

只在有可靠历法计算或核实来源时把候选支、旬或节令转换成公历日期；本 CLI 目前不提供
应期搜索功能，不能声称工具已计算成功概率或最优日期。未来干支可用固定同一组
`--lines` 和目标时间做历法复核，但必须标为“候选日期核验”，不能把其月日替换原盘来
重新判断原问题，不能再次随机摇卦。使用原盘相同的 `calendar.zi_hour` 日界规则与
节气基准（缺省为 23 点换日），不能在原盘与候选日期之间无声切换流派。

输出应包含：候选窗口、对应爻位、原状态、触发规则、阻碍／反例、仍需满足的现实条件。
候选冲突或无法确定远近时，明确说无法缩到唯一日期；禁止把“出空”写成必到账、
把“逢合”写成必签约。实际结果反馈应与原判断并列保存，不能修改原预测来消除失误。
